# Hyperledger Fabric – 2-Org Network with Java Chaincode

## Architecture

```
fabric-network/
├── docker-compose.yaml          # All containers (CA × 2, Orderer, Peer × 4, CLI)
├── network/
│   ├── configtx/
│   │   └── configtx.yaml        # Channel profiles, MSP definitions, policies
│   └── crypto-config/
│       └── crypto-config.yaml   # Org/peer/user topology for cryptogen
├── organizations/               # Generated by cryptogen (gitignored)
│   ├── orderer/
│   ├── org1/
│   └── org2/
├── chaincode/
│   └── asset-transfer/          # Java chaincode (Maven project)
│       ├── pom.xml
│       └── src/
│           ├── main/java/org/hyperledger/fabric/samples/
│           │   ├── Asset.java          # Data model
│           │   └── AssetTransfer.java  # Contract (CRUD + Transfer)
│           └── test/java/org/hyperledger/fabric/samples/
│               └── AssetTransferTest.java
├── application/                 # Java client (Fabric Gateway SDK)
│   ├── pom.xml
│   └── src/main/java/org/fabric/client/
│       └── App.java
└── scripts/
    └── network.sh               # One-stop network management script
```

## Quick Start

### Prerequisites

- Docker & Docker Compose
- Hyperledger Fabric binaries 2.5.x in `./bin/`
  ```bash
  curl -sSL https://bit.ly/2ysbOFE | bash -s -- 2.5.4 1.5.7
  ```
- Java 11+, Maven 3.8+

### 1. Start the network

```bash
chmod +x scripts/network.sh
./scripts/network.sh up
```

### 2. Create the channel

```bash
./scripts/network.sh createChannel
```

### 3. Deploy the chaincode

```bash
./scripts/network.sh deployCC
```

This will:
1. `mvn clean package` the Java chaincode into a fat jar
2. Package the chaincode archive (`asset-transfer.tar.gz`)
3. Install on `peer0.org1` and `peer0.org2`
4. Approve for both organizations (satisfies the MAJORITY endorsement policy)
5. Commit the chaincode definition to `mychannel`
6. Invoke `InitLedger` to seed 6 sample assets

### 4. Run the client application

```bash
cd application
mvn clean package -q
java -jar target/app.jar
```

### 5. Tear down

```bash
./scripts/network.sh down
```

## Chaincode Contract API

| Function | Type | Description |
|---|---|---|
| `InitLedger` | SUBMIT | Seed ledger with 6 sample assets |
| `CreateAsset(id, color, size, owner, value)` | SUBMIT | Create a new asset |
| `ReadAsset(id)` | EVALUATE | Read one asset |
| `UpdateAsset(id, color, size, owner, value)` | SUBMIT | Overwrite all fields |
| `DeleteAsset(id)` | SUBMIT | Remove asset from world state |
| `TransferAsset(id, newOwner)` | SUBMIT | Change owner, returns old owner |
| `AssetExists(id)` | EVALUATE | Returns boolean |
| `GetAllAssets()` | EVALUATE | Returns JSON array of all assets |

### CLI examples (from inside the `cli` container)

```bash
docker exec -it cli bash

# Query all assets
peer chaincode query -C mychannel -n asset-transfer \
  -c '{"function":"GetAllAssets","Args":[]}'

# Create an asset
peer chaincode invoke -o orderer.example.com:7050 \
  -C mychannel -n asset-transfer \
  --tls --cafile /path/to/orderer/tls/ca.crt \
  -c '{"function":"CreateAsset","Args":["asset7","purple","10","Alice","900"]}'

# Transfer an asset
peer chaincode invoke -o orderer.example.com:7050 \
  -C mychannel -n asset-transfer \
  --tls --cafile /path/to/orderer/tls/ca.crt \
  -c '{"function":"TransferAsset","Args":["asset1","Bob"]}'
```

## Endorsement Policy

Default policy is `MAJORITY Endorsement`, meaning **at least one peer from each org must endorse** every transaction. This is defined in `configtx.yaml` under `Application.Policies.Endorsement`.

## Running Chaincode Tests

```bash
cd chaincode/asset-transfer
mvn test
```

## Key Design Decisions

- **Fabric 2.5 lifecycle** – chaincode is installed and approved per-org before committing, enabling independent upgrades per organization.
- **Raft orderer** – single orderer node for development; add two more Raft consenters for production fault tolerance.
- **Java chaincode** – uses the official `fabric-chaincode-java` SDK with `Genson` for JSON serialization and the `ContractInterface` annotation model.
- **Fabric Gateway SDK** – the client application uses the newer Gateway API (replaces the legacy `fabric-sdk-java`), which provides cleaner async/sync transaction submission.
- **TLS everywhere** – all inter-component communication is TLS-encrypted including peer-orderer, peer-peer, and client-peer channels.
